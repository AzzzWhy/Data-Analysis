## 时间与加速比

两个规模使用相同投影列 `region,revenue`，同样的三个操作：收入摘要、IQR 异常值（展示前三条）、按地区收入求和（前三组）。固定报表为四份计划，展示 K 分别为 1/2/3/4，共十二个结果，事务内九个步骤复用精确结果。数据读取是全量，不抽样；各显式路径结果相互一致，共享事务也与独立 CPU 计划核对一致，浮点数使用相对/绝对 `1e-9` 容差。

下表为输出压缩修复前的 3 次测量中位数，单位秒；不含模型。热工作先预热，冷启动每次新建并关闭对应进程，保留操作系统文件缓存。修复后只重验工具与模型调用链，没有重复性能校准；统计计算代码没有改变，但不将原测量当作修复后重新计时。

| 场景 | 行数 | 纯 CPU | GPU 原生 | CPU 读取→GPU | 自动实际选择 | CPU ÷ 所选路径 |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| 三步分析，热 worker | 20,000 | 0.00790 | 0.02807 | 0.02618 | CPU | 1.00× |
| 三步分析，热 worker | 113,500,327 | 3.61950 | 0.81942 | 1.16041 | GPU 原生 | 4.42× |

| 三步分析，冷 worker，含启动/退出 | 113,500,327 | 3.94759 | 2.45663 | 2.29313 | GPU 原生（保守裕量） | 1.61× |
| 四份报表，热队列 | 20,000 | 0.02378 | 0.03075 | 0.02839 | CPU | 1.00× |
| 四份报表，热队列 | 113,500,327 | 3.64084 | 0.83780 | 1.17676 | GPU 原生 | 4.35× |

比值使用同一行的显式路径中位数，不将冷态 CPU 与热态 GPU 混算。热队列自动请求的实测中位数另外是 0.02399 / 0.83968 秒，故包含自动决策开销后的大数据比值约 4.34×。

**自动路由不是每种条件下的绝对最短耗时。** 单批混合路径需要同时通过读取、计算及完整耗时裕量；本次超大数据冷单批的混合路径虽比原生 GPU 快约 6.7%，仍没有达到 10% 完整耗时收益门槛，因此保守保留原生 GPU。完整固定报表则按 `reports_cold` 事务策略选中了混合路径。这是不同场景的明确策略，不应宣传为任意输入都会选理论最优。

相对本次更新前的机器核心备份，大数据原生 GPU 热单批由 0.84429 降到 0.81942 秒，约 3.0% 速度提升。只有三轮复测，不能将小幅变化当成长期保证，也不能据此证明已达到硬件极限。历史七档实验仍见 [七档结果](ALL_SCALES_RESULTS.md)，本次只重新验收小数据与超大数据两个端点，没有宣称七档全部重跑。

同一超大数据四报表清单：每次新建队列 CLI 的中位数 2.43491 秒，常驻报表服务稳态中位数 0.86803 秒（首次服务请求 1.97414 秒，服务 ready 0.17856 秒另计），约 2.81×。四份完整报表数值一致，服务正常退出；该比值反映进程复用收益，不能写成 CPU/GPU 加速比。

首轮模型完整对话耗时小数据 17.68 / 20.87 秒，大数据 29.11 / 22.90 秒，包含模型规划、工具调用和最终回答，不能等同于上表分析时间。修复后的完整调用耗时另保存在验收 JSON 中。当前演示体验的下一瓶颈主要在模型调用链，继续压缩不足一秒的 GPU 分析不一定显著改善总对话延迟。

## 启动已部署核心

新增启动脚本只设置**本次进程**的 RAPIDS 解释器、引擎位置、CUDA 位置及已有 Agent 校准文件；不修改用户连接配置或 shell 启动文件：

```bash
cd ~/Data-Analysis-unified
bash scripts/run_gb10_core.sh agent
```

使用已经运行的本机无鉴权模型时（`local` 只是占位值，不是外部密钥）：

```bash
GPU_API_KEY=local bash scripts/run_gb10_core.sh agent --base-url http://127.0.0.1:8000/v1 --model qwen3.6-35b-a3b-fp8 --language zh
```

高频固定报表服务：

```bash
bash scripts/run_gb10_core.sh service --output-root reports/service
```

报表计划中的 `hybrid_profile` 继续指向验收目录下每个规模的 `profiles/<rows>.json`，其中同时保存 `reports_cold` 与 `reports_warm`，不使用 Agent 的 `batch_*` 校准冒充报表校准。Agent 默认校准是 `~/gpu-analysis-release-6e287a2/acceptance/agent-profile.json`；文件或任务变化、环境变化、24 小时过期时不再命中，正常请求仍能回退运行。演示前需要重新校准时，用验收脚本与本机保存的清单明确发起实验，不在对话中偷偷三路重跑。

启动脚本经 shell 语法检查和三个入口的 `--help` 验证。若 GPU 环境安装在不同目录，设置 `GPU_ANALYTICS_PYTHON` 与 `CUDA_PATH`；GUI 若不使用启动脚本，需在它启动 worker **之前**传递相同进程环境。
