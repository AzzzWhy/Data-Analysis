# 新公开数据测试（2026-09-29）

本目录保存新一轮 GB10 数据测试的脱敏结果和来源信息。原始数据、转换后的数据以及包含机器和路径标识的校准配置只保留在实验机器；不纳入仓库。测试不涉及 GUI。

## 结论

三份公开数据、八组工作负载完成了全量分析。可用 CPU / 原生 GPU / CPU 读取＋GPU 计算路径、未经本轮校准的自动模式和校准后的自动模式，其返回的统计、相关矩阵、异常值及分组 Top-K 均与独立 CPU 执行一致。传感器数据适合 CPU；零售字符串分组受益于 GPU；500 万行 SUSY 宽表的同模式 CPU/GPU 比为 **3.02×**。

不能把这轮结果描述成“所有场景 GPU 最快”或“Agent 已经能在未知数据上保证最优”。尤其是零售按国家、客户编号分组，没有匹配校准时选择 CPU，校准后才选择更快的 GPU。本轮校准是实测配置查找，不是训练大语言模型，也没有修改默认 Agent 的生产校准文件。

传感器原始十批全部按原始顺序保留，映射 128 个特征编号，额外增加来源批号，因此准备后的表有 130 列。零售保持八列，客户编号等标识转换为可空文本；保留 243,007 个缺失客户编号、4,382 个缺失描述以及负数退货数量。SUSY 保持类别列及 18 特征，全部 float64，不降精度。

转换后逐表校验保存的 Parquet；SUSY 以 25 万行一块，重新读取完整压缩源文件，与保存的每个行组逐值精确核对。三份数据的原始压缩包及 Parquet SHA256、类型、缺失计数和准备用时分别见 source-gas.json、source-retail.json、source-susy.json。

## 方法与口径

- 每组四项分析：描述统计、Pearson 相关性、前两数值列的异常值、指定键的分组。窄表只选择两数值列；传感器宽表统计全部 128 特征，相关性计算前 18 特征；SUSY 宽表统计和相关性均覆盖全部 18 特征。
- 全量读取所需列，不抽样、过滤、填补或人为复制数据。分组完整聚合，但展示 Top-5；异常示例展示 Top-3，不宣称展示了所有分组或异常行。
- 计时包含请求、读取、转换、计算及返回结果。每条显式执行路径先一次不计时预热，再三次交错执行取中位数。自动模式三次取中位数。毫秒级及几个百分点的差距不视为可靠优势。
- 独立 CPU 基线为四次独立 Python 进程；热进程逐项模式每项重新读取；单批次为四项共享一次读取。跨请求数据帧缓存关闭，操作系统文件缓存保留。热模式不含工作进程首次启动，本轮首次启动单独记为 0.6382 秒。
- 双报表模式执行两份**相同**的四项计划，共八个逻辑请求；允许同一事务精确复用结果。复用必须扫描数为零、来源行数正确，且与前面已全量扫描的结果一致。不能把此模式的收益推论成任意八项不同分析都同样快。
- 输出按既有校验器以相对/绝对误差 1e-9 比较数值，字段、列表顺序及非数值严格相同；不一致或回退的路径不计入成功 GPU 计时。文本/时间投影的 CPU→GPU 加载拒绝单列记录，不伪装成 GPU 成功或内存不足。
- 每条单批次和双报表路径分别使用匹配的 warm 校准配置。未测冷进程 GPU、LLM、网络 API 延迟、定时调度或 GUI 端到端速度；数据准备不计入分析用时。没有清除其他项目的缓存、模型或进程。

## 四项单批次：同模式 CPU/GPU 比较

单位为秒。GPU 加速比 = 热 CPU 单批次 / 热原生 GPU 单批次；小于 1 表示 GPU 更慢。“自动”为本轮匹配校准后实测，而非默认生产配置。

| 场景 | 行数 | CPU | 原生 GPU | CPU→GPU | 自动实测 | 自动选择 | GPU 加速比 |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| 传感器窄表 | 13,910 | 0.0104 | 0.0241 | 0.0248 | 0.0127 | CPU | 0.43× |
| 传感器 128 特征 | 13,910 | 0.0714 | 0.4007 | 0.4069 | 0.0672 | CPU | 0.18× |
| 零售数值 | 1,067,371 | 0.0693 | 0.0763 | 0.0669 | 0.0712 | CPU | 0.91× |
| 零售国家分组 | 1,067,371 | 0.1477 | 0.0924 | 不支持该投影 | 0.0909 | 原生 GPU | 1.60× |
| 零售可空客户编号 | 1,067,371 | 0.1571 | 0.0971 | 不支持该投影 | 0.0960 | 原生 GPU | 1.62× |
| 零售时间分组 | 1,067,371 | 0.0814 | 0.0787 | 不支持该投影 | 0.0797 | CPU | 1.03× |
| SUSY 窄表 | 5,000,000 | 0.4005 | 0.2411 | 0.2425 | 0.2413 | 原生 GPU | 1.66× |
| SUSY 18 特征 | 5,000,000 | 3.9507 | 1.3071 | 1.2856 | 1.3053 | 原生 GPU | 3.02× |

零售数值的混合路径仅约 3.4% 更快；时间分组的 GPU 仅约 3.4% 更快。单批次策略要求 GPU 有明确收益、混合路径同时满足读取/计算/全程收益门槛，因此选择 CPU/原生 GPU 而非追逐极小时间差。SUSY 宽表混合与原生约差 1.7%，单批次仍选择原生 GPU。

## 自动选择暴露的不足

| 工作负载 | 没有本轮校准 | 匹配校准后 | 说明 |
| --- | --- | --- | --- |
| 传感器两组 | CPU | CPU | 避免小数据强上 GPU |
| 零售数值、时间分组 | CPU | CPU | 候选差距小，保守选择合理 |
| 零售国家、可空客户分组 | CPU | GPU | 仍有未校准选路盲点；只看行数和数值解码体积不足 |
| SUSY 两组单批次 | GPU | GPU | 现有门槛在这两组上有效 |
| SUSY 宽表双报表 | 原生 GPU | CPU→GPU | 使用报告事务的匹配实测记录 |

建议下一步优先补未知工作负载的低成本校准/成本模型，加入分组键类型、基数、列数、压缩比和算子组合，而不是继续提高一个固定行数阈值。校准必须使用同一文件、列投影、完整参数、机器和执行上下文；不得跨冷/热或单批次/报表借用时间，已有配置也不能代表未知数据。

## 证据、环境与复现

results.json 保留三次原始计时、读取/转换/计算分解、实际选路、复用计数和自动决策原因；runtime.json 保存实际运行源码的 SHA256。测试使用 GB10、20 个逻辑 CPU、aarch64、Python 3.11.16、pandas 2.3.3、PyArrow 21.0.0、cuDF 25.10.00、CuPy 14.2.0、CUDA runtime 13020、驱动 580.126.09。

核心算法和混合选路源码与本地一致。gpu_session.py 原始文件哈希因混合换行不同而不同；两端将 CRLF 规范化为 LF 后，SHA256 均为 `c3dcd28124e901024669291cfbe84a5224ca9748004b9c626726d6f72d885a30`。未为这轮测试修改核心算法或 GUI。

运行时指定项目目录与实验目录；以下 `$EXPERIMENT_DIR` 必须由使用者指定为其自己的独立实验目录，原始官方 ZIP 放在该目录的 raw 子目录。零售准备需要 openpyxl，本次使用实验目录内的独立依赖，不改 RAPIDS 环境。

```bash
python benchmark/prepare_new_public_data.py --root "$EXPERIMENT_DIR" --dataset gas
python benchmark/prepare_new_public_data.py --root "$EXPERIMENT_DIR" --dataset retail
python benchmark/prepare_new_public_data.py --root "$EXPERIMENT_DIR" --dataset susy
python benchmark/public_diversity_benchmark.py --root "$EXPERIMENT_DIR" \
  --output "$EXPERIMENT_DIR/results" --repeats 3
```

使用正确的 RAPIDS Python 与 CUDA_PATH；如已有输出，可另设实验输出目录，不覆盖原始数据。本轮最终八组通过，测试进程的活跃会话和数据帧缓存均归零；测试脚本的五项契约检查在本地和 GB10 均通过。早期脚本调试失败记录仅保留在 GB10，不纳入最终计时。测试完成时结果只保存本地；随后用户授权将脚本和脱敏记录随核心收尾提交发布。原始数据、实验校准和机器私密连接信息不随提交上传，默认 Agent 配置也没有因此改变。
