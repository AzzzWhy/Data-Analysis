# 整合版与独立分支、纯 CPU 的同数据复测（2026-09-28）

## 条件

- 机器：同一台 GB10。数据：2017 年 TLC 出租车数据提取的 `region`、`revenue` 两列，原始 Parquet 113,500,327 行；小档为原始文件前 N 行，无复制扩增。
- 每轮依次做 `revenue` 摘要、离群值前三、按 `region` 汇总 `revenue` 前三。每个后端的会话与批量计算结果一致，输入文件未变，结束后没有残留会话。
- 整合版每种行数和后端各交替测量会话/批量 5 次，取中位数。两种流程都是一次读取、三项分析，不含 LLM；文件系统缓存不清空。工作进程启动约 0.64–0.69 秒，单独列出，不计入下面的热路径耗时。首次 GPU 调用的初始化峰值也不代表稳态中位数。
- 旧热工作、旧批量数据取自此前同机、同输入和同三项分析的 [七档记录](../scale-results.jsonl)，各 5 次。旧热工作是三次独立分析、三次读取；整合版对话会话是打开一次后连续分析三次。旧批量和新批量均为一次读取。纯 CPU 独立进程取自 [历史基线](../cpu-independent-results.jsonl)：每项分析新建一个 CPU 进程，共三次，包含启动/导入，不清除文件缓存。历史与本次不是同一时刻测量，百分之几的差别不宜解读为确定的优化。
- 本目录的 21 个 `tlc-*.json` 保存整合版每档、每后端的 5 次原始耗时、加载路径、启动时间和一致性校验结果。`cpu` 为 pandas 读取及计算；`cpu_gpu` 为 CPU 读取、GPU 计算；`native` 为 GPU 直接读取及计算。

最后一列是**完整三项流程的生命周期收益**，并非纯 GPU 算术加速：旧基线反复启动进程，新版复用进程且只读取一次。旧批量与新批量相差约 ±5%，没有可靠的额外提速证据。整合的主要收益在对话会话：它由三次读取变成一次读取。

## 整合版实际应选哪条计算路径

下表统一使用整合版批量的“一次读取、三项分析”流程，避免将流程差异误作 GPU 加速。单位仍为秒；相对纯 CPU 倍数 = 本表 CPU 耗时 / 该路径耗时。

这组两列窄表说明：小档应选 CPU；中档混合路径能占优；大档直接 GPU 读取更快。不同格式、列宽、操作及缓存状态会改变拐点，不能把这些行数硬编码成全局策略。1.135 亿行的整合版会话分别为纯 CPU 4.0183 秒、混合 1.8472 秒、直接 GPU 1.5291 秒，与批量结果相近。
