# 七档冷启动报表校准（GB10，2026-09-29）

在同一 GB10、同源双列数值 Parquet 数据和四份固定报表上，分别完整启动/退出队列 CLI 与分析 worker，保留操作系统文件缓存，不含模型推理。每档先预热一轮，再交错执行 CPU、原生 GPU、CPU 读取＋GPU 计算各三轮，表内显式路径为中位数；最后另起一次自动执行，验证实际路径、结果一致和源文件未变。校准本身的实验时间**不计入**自动执行耗时。该轮在隔离目录运行，未改变旧部署或发布仓库。

[去标识化逐轮原始耗时](hybrid-evidence/cold-calibration-20260929.json)保留了各档三次显式路径用时及自动验收结果；本机 profile 与完整报告留在 GB10，不上传包含设备或源文件绝对路径的文件。

先前[七档五轮测试](ALL_SCALES_RESULTS.md)的冷启动自动路由在 5000 万行选原生 GPU、耗时 2.187 秒，在 1.135 亿行选原生 GPU、耗时 2.605 秒；同轮显式混合路径分别是 1.827 和 2.443 秒。此次新增冷态校准后，两档自动路由均实测选中混合路径，单次自动验收分别为 1.801 和 2.450 秒。两轮测试的重复次数、时间窗口不同，不能把 2.187/1.801 或 2.605/2.450 直接宣称为稳定加速倍数；可靠结论是修正了这两档的**错误路径选择**，且同轮自动验收接近所选显式路径。其余五档仍选择 CPU，没有为 GPU 初始化付出额外开销。

另外用 5000 万行的已校准清单交错测试新进程队列与常驻报表服务各三轮：前者实际路径均为 `cpu_gpu`，中位数 2.152 秒；后者首次请求记录为冷态 `cpu_gpu`，随后三轮均为热态 `native_gpu`，中位数 0.808 秒。两者复用程度及启动边界不同，这组数字只验证各自使用了正确上下文，不是可互换的单一加速比。冷态路由的 24 项单元测试，以及报表、队列、工作进程、交互复用、混合批次、GPU 协调和服务合计 55 项回归测试均通过；另用一个全新 profile 路径完成 2 万行从零校准和自动验收。

适用边界：这是单机、同一份数据的前缀规模、同一组四报表的结果；宽表、其他格式、不同算子或文件缓存状态可能改变胜者。校准记录绑定本机软硬件、文件身份、投影列、完整步骤和冷/热上下文，24 小时失效；失效后回到既有保守路由，不会假装仍有有效训练。常驻服务使用独立的热态校准，不继承这份冷态结果。代码及使用方式见[统一执行说明](UNIFIED_EXECUTION.md)。
