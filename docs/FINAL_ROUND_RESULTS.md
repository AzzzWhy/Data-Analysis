# 最后一轮算法与端到端优化（GB10，2026-09-28）

本轮保留两项经验证的改动：对低基数、重复数值列，以**全量频数**计算精确顺序统计量；对重复提交的固定报表，提供一个可选的本地常驻进程，复用分析 worker。前者不抽样计算答案，后者不跨请求缓存数据帧。两个入口均保留旧执行方式，统计优化还可用 `GPU_ANALYSIS_FREQUENCY_STATS=0` 立即回退。

测试环境为 GB10 上隔离的候选代码目录。对照版本是本轮开始时已部署的统一实现；未在对照过程中修改原有项目、输入数据或模型服务。数值为五轮交错测试中位数，均核对结果一致和原文件身份不变。单次工作流为同一份 Parquet 上的摘要、IQR 异常值及区域收入汇总；四报表为同一数据上不同 top-K 的四份完整报告。下表单位为秒；“单次”不含进程启动、LLM 或网络推理。

亿级原生 GPU 单次比对照快 **1.68 倍**，相对本轮 CPU 单次快 **4.43 倍**。这不是所有规模、格式和算子的通用加速比：两万行显式 GPU 路径反而较慢，自动路由选择了 CPU。百万行混合路径略胜原生 GPU；亿级则原生 GPU 更合算。四报表热队列的成绩不能直接当作单份分析耗时。三档报告均与独立 CPU 计算逐项一致，四报表在同一事务中复用 9 个步骤的结果，没有跨请求复用旧数据。

单列摘要的机制对照：亿级数据原生 GPU 原统计路径 **0.7801 秒**，全量频数路径 **0.2087 秒**（3.74 倍）；该列有 23,100 个不同值。百万行同列为 0.01209 → 0.00749 秒。207 万行真实家庭用电数据的 `Global_active_power` 不符合本轮候选收益条件，自动保留原路径：0.02185 → 0.02279 秒（候选调用包含守卫检查）；结果一致。这说明算法有适用边界，不应强制用于高基数、窄幅大偏移、非有限值或内存不足的数据。

亿级四报表的**端到端**调用另测：每次新启动队列 CLI 为 **2.5749 秒**，复用本地常驻报表进程为 **0.8790 秒**，约 **2.93 倍**。常驻进程首次请求仍需启动 worker，实测 **2.1723 秒**；服务自身就绪耗时 **0.1711 秒**。因此只有重复提交时才有显著收益。两种方式生成的四份结果一致，源文件未变，常驻服务正常退出。服务不监听网络端口；它通过标准输入接收一行 JSON 请求，退出时关闭所拥有的 worker。

GB10 隔离目录通过 80 项指定回归测试，覆盖统计边界、报表服务、队列、交互复用、混合路由和 GPU 许可。另一次百万行真实设备联测确认两个 CPU 进程重叠、GPU 作业串行、热会话等待共享许可后继续，结果一致，结束后活动会话数为零。测试不是全仓库所有数据和未知负载的最优性证明；模型推理延迟亦未计入。
