# 本地优化实现与验证

状态：四项优化已实现并验证；GB10 只在独立临时目录验证，未覆盖现有 Agent。发布情况以 Git 提交记录为准。

## 四项实现

1. **自动列裁剪**：明确指定分组键与聚合列时，只读取所需列。summary、corr、outliers 明确指定 columns 时也可裁剪。profile、auto、未指定指标保留完整表。显式 usecols 优先；`--no-auto-usecols` 可做整表读取对照。
2. **列式缓存**：显式设置 `GPU_ANALYSIS_PARQUET_CACHE_DIR` 后，首次读取完整 CSV 并生成完整 Parquet，返回所需列；下一问可选不同列命中同一缓存。驻留会话也使用该缓存。首次转换成本如实计入；行数受限的读取不使用缓存。源文件不被修改，文件版本或解析引擎版本变化会失效；旧磁盘缓存不会自动删除。
3. **交互复用**：TUI 和基本交互终端的单步问题可以复用有容量/TTL 限制的完整 GPU frame。每次工具请求仍重新计算，不复述上次模型答案；不保留活动会话或计划。小文件、内存不足、worker 无法打开时回到原有 stateless 路径。单次 `--ask` 不改变语义。设 `GPU_ANALYSIS_RESIDENT_INTERACTIVE=0` 可关闭自动复用；原有 warm-cache 容量/TTL 开关仍有效。
4. **算子优化**：异常值检测先数 mask，再仅筛选示例需要的列，避免复制整张宽表。summary 从已有非空计数推导空值数，避免重复扫描。精确分位数、IQR 容差、样例顺序和数值精度不变。批量归约方案经 cuDF 25.10 实测反而变慢，已撤回。

没有实施隐式分区改写、近似分位数、降低数值精度或自定义 CUDA 算子。

## GB10 现场验证（2026-09-27）

数据为已有合成销售数据；GPU 为 GB10，cuDF 为 25.10。模型服务保持运行，不修改其配置。

| 验证 | 结果 | 口径 |
| --- | --- | --- |
| 20M 行 groupby 自动两列裁剪 | 整表约 2.59s，按列约 2.19s | 两次读取测试平均；前三名数值一致；不含 LLM |
| 20M 行完整 outliers 操作 | 原版中位约 0.243s，新版约 0.228s | 各三次、交替执行、已有驻留数据；完整结果在容差内一致 |
| 20M 行 CSV 首次 Parquet 转换 | 约 2.55–2.60s | 首次完整转换，缓存约 1.24GB，成本计入 |
| 转换后只读 region/revenue | 约 0.060–0.147s | 两次独立验证中的热缓存读取；不是全流程加速倍数 |
| 5M 行实际 worker 连续 groupby | 首次工具约 1.40s，第二次约 0.014s | 第一问加载、第二问复用；统计结果一致；不含 LLM、worker 启动及首次 list 请求 |

20M 行首次驻留验证曾因空闲约 12.4GB、门槛约 12.5GB 被拒绝。保留内存保护，不降门槛来“跑通”测试。
后续大文件请求仍验证可完成，结束后活动会话为零。空闲内存变化会影响是否进入驻留路径。

这不是对所有文件的速度保证。列裁剪也加速 CPU；此前同一任务 CPU 从约 10.57s 降至 6.08s，所以 GPU/CPU 倍数反而下降。
完整 Agent 还包含模型等待，不能把 0.014s 或缓存读取时间说成用户收到答案的时间。

## 对照准确性与测试

- CPU 对照缓存新增版本标识，旧整表读取成绩不与新投影成绩混用；文件版本使用纳秒修改时间。
- 不同查询参数不共用 CPU 基线；缓存转换/命中不引用不匹配的冷读 CPU 倍数。
- 投影读取和 Parquet 缓存读取不使用旧整表 CSV 的耗时拟合。
- CPU-only 优化、交互复用、路由、工具接口、分组完整性、计划测试可在本地运行。
- API 配置和 TUI 测试使用模拟请求，无收费模型调用。

GB10 集成验证脚本（在所有脚本与 agent/skills.py 可导入的隔离测试目录运行）：

```bash
python optimization_validation.py \
  --source /path/to/large.csv \
  --baseline /path/to/unmodified/gpu_analytics.py \
  --resident-source /path/to/gpu-routed-smaller.csv
```

验证要求合成销售字段 region/revenue；baseline 必须是未改版本。脚本会创建并清理临时 Parquet 副本，不修改源 CSV。
真实 worker IPC 另做了两次交互工具调用验证；脚本内复用测试直接调用 worker handler，不依赖模型。
