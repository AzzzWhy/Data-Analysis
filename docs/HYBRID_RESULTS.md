# 热工作进程混合执行：第一版实测

日期：2026-09-28。分支：`codex/hybrid-warm-worker`，方向：CPU 加载＋GPU 计算 · 热工作进程。代码与脱敏结果发布到本实验分支；实验在隔离目录运行，不合并 main、不替换正式部署。

## 实现口径

复用解释器和 CUDA 上下文；每个请求重新 CPU/PyArrow 投影读取、转换为 cuDF、执行 GPU 计算，结束释放数据。不跨请求缓存帧或分析结果。校准比较全 CPU、GPU 原生读取、CPU 加载＋GPU 计算的完整请求时间；只有混合读取、计算及包含转换的总成本都满足收益门槛时，自动选择混合。

## GB10：113,500,327 行真实 Parquet

同一文件、相同列和操作，每条路径五次交错测试，以下为请求墙钟时间中位数，单位秒。结果全量比对通过，浮点容差 1e-9，源文件未变化。

| 单次查询 | 全 CPU | 原生 GPU | CPU 加载＋GPU 计算 | 自动选择 |
|---|---:|---:|---:|---|
| revenue 摘要 | 2.594 | 1.035 | 1.221 | 原生 GPU |
| revenue 异常值前三例 | 2.642 | 1.229 | 1.409 | 原生 GPU |
| region 分组 revenue 求和前三组 | 0.828 | 0.295 | 0.630 | 原生 GPU |

工作进程启动单列：0.655 秒。首次原生 GPU 摘要请求为 1.590 秒，包含读取器延迟初始化；五次中位数不能当作所有请求都无首启开销。各查询中位数也不能相加后称作一次批量请求实测。

三个查询的混合实现均正常执行真实 GPU 计算，但此亿级数据的原生 GPU 读取更合算，转换增加了成本。保存校准后再次实际调用 `auto`，三个查询均选择原生 GPU，输出及全量行数一致。**该亿级数据没有混合超过原生 GPU 的正收益。**后续百万行分规模测试已得到混合正收益，三个查询也均实际自动选择混合，详见 [分规模实测及普通 CPU 基线](HYBRID_SCALE_RESULTS.md)。

## 小数据与回归

20,000 行带空值的数值 Parquet，三个查询、冷/热两种生命周期、每条路径各两次测试通过。全 CPU、原生 GPU、混合全量输出一致，实际 `auto` 均选择 CPU。小数据样本数仅用于功能验收，包含首次读取器初始化，不作为严格稳态性能排名。

公共混合模块十六项、原有执行十三项、交互五项、优化九项、统计十二项，以及工具契约、执行决策和计划断言本地通过。GB10 公共混合测试和真实 GPU 小数据 smoke 通过。初次 GB10 测试因缺少 psutil 正确识别降级并拒绝写入 GPU 校准；随后使用 Linux `/proc/meminfo` 获取可用内存，未给正式环境安装依赖。测试结束后本地模型真实推理返回 OK，未停止或修改模型服务。

## 范围与限制

- 仅平坦数值/布尔 Parquet；CSV、零拷贝、异步流水线和跨请求数据缓存尚未实现。
- 保留内存预算保护和文件变化拒绝，不能用 CPU 重读绕过拒绝。记录的是预算及可用内存快照，不是实际峰值内存采样。
- 未清系统文件缓存；模型保持运行。结果限于这台机器、此文件和查询，不证明所有数据规模的收益。
- 校准仅由显式评测建立，24 小时有效，绑定文件、完整查询、冷热状态和设备环境；无匹配记录沿用原路由。
- 原始日志保留在本地实验材料目录；设备指纹、机器地址、密钥和校准配置不提交仓库。

使用入口见 [实现与使用说明](HYBRID_EXECUTION_PLAN.md)。批量方向在 `codex/hybrid-batch`，其请求内共享一次加载和统计，不混入本分支成绩。
