# 批量分支混合执行验证（2026-09-28）

本地开发分支 `codex/hybrid-batch`，没有推送 GitHub，没有合并 main，没有替换 GB10 部署或修改模型。测试在独立临时目录 `/tmp/gda-hybrid-batch.dIyRYM`；已有原始数据保持不变。

## 已实现

CPU/PyArrow 投影读 Parquet、一次 Arrow→cuDF 转换、一次批内数据加载、按步骤共享精确统计、确定性关闭独占会话。默认 `auto` 只接受完整结果一致的匹配校准；无校准使用原有路由，收益不足选择 CPU 或原生 GPU。校准有内存/大小界限、24 小时时效、文件/设备/环境/查询/冷热状态绑定，不扫描额外基线来回答普通问题。

初版仅支持平坦数值/布尔列。转换失败可以报告 CPU 降级，但内存保护和输入变更拒绝不允许以降级绕过。报告加载引擎、实际计算引擎、读取与转换次数、CPU 读取时间、转换时间和初始化，逐步真实引擎仍需检查。

## 真实 113,500,327 行实验

同一 TLC 两列 Parquet、相同三项分析：revenue 摘要、异常检测前三例、region/revenue 求和前三组。cuDF 25.10.00，pandas 2.3.3，GB10。每路径五次，正逆序交错，表为墙钟中位数，包含读取、转换、计算及 worker 通信，不含 LLM。

| 路径 | 总耗时 | 读取 | 转换 | 计算 |
|---|---:|---:|---:|---:|
| 全 CPU 批量 | 3.979 秒 | 0.338 秒 | 无 | 3.642 秒 |
| GPU 原生批量 | 1.533 秒 | 0.131 秒 | 无显式 Arrow 转换 | 1.367 秒 |
| CPU 加载＋GPU 批量 | 1.858 秒 | 0.171 秒 | 约 0.284 秒 | 1.361 秒 |

混合路径确实使用 GPU，CPU 读取与转换各一次，三路径全量行数与输出容差 1e-9 内一致；批内异常检测复用摘要统计，批后活动会话与热帧均为零。自动路由保存校准后再次实际调用 `auto`，选择并执行原生 GPU，结果再次一致。

混合比全 CPU 约快 2.14 倍，但比原生 GPU 慢约 21%；不能把它称为新增优化收益。原生 GPU/CPU 约 2.60 倍。该材料不满足“CPU 读取更合算”的实测条件，保护性选择符合目标；目前没有真实混合胜过原生 GPU 的正例。

worker 首启另计 0.645 秒；首个原生读取仍含延迟初始化，总时间 2.088 秒，其余原生样本约 1.521–1.553 秒。没有清系统文件缓存、没有停止本地模型，不是全部严格热态或冷缓存上限实验。读取和计算分项为各自中位数，不要求相加恰好等于端到端中位数。

首次三次原型试验也一致：CPU 4.001 秒、原生 GPU 1.546 秒、混合 1.848 秒。初版缺少 psutil 的失败被明确识别为 CPU 降级，校准中止；改用 Linux MemAvailable 后重测通过，未将失败结果作为 GPU 成绩。

## 回归与限制

本机公共混合测试十六项、批量测试八项、现有执行十三项、交互五项、优化九项、统计十二项通过；工具接口、执行决策、计划和 CPU 冒烟通过。本机没有 cuDF，原有显存容量与大文件会话测试不能据此声称通过。

GB10 公共混合测试十六项、批量测试八项再次通过，真实 GPU 的 20,000 行冒烟通过。另用 20,000 行带空值 Parquet，冷/热批量生命周期各测试三路径两次，全量结果一致、每批读取和转换各一次、结束没有活动会话；实际自动选择均为 CPU。热批量 CPU 中位数 0.00608 秒、混合 0.01208 秒；样本仅用于功能验收，首次读取器初始化未完全摊销，不据两次样本发布严格稳态排名。

所有实验结束后，本地模型真实推理返回 OK；模型服务未停止或改配置，未清系统缓存。

尚未实现 CSV 混合解码、动态背景校准、在线实际内存峰值采样、零拷贝、异步双缓冲或跨请求数据缓存。内存记录为保守预算及当前可用内存，不是测得的峰值。五次样本仍只是此数据与任务的工程验证，不保证所有模型或数据加速。
