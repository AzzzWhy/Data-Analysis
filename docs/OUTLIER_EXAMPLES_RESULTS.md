# 有界异常示例提取：GB10 对照（2026-09-29）

这轮只优化分析核心，不修改 GUI。原路径先筛出全部异常行，再取前 K 行；新路径仍全量计算异常掩码、计数、比例和边界容差，但示例提取从前 1024 行开始，按四倍扩大前缀，找到足够示例就停止。例子仍按原始行序返回，不抽样答案。小于等于 10 万行或所有匹配行都需展示时，保留原筛选路径。若异常集中在文件末尾，前缀可能增长至全文件，不保证所有分布都更快。

## 同轮完整工作流

同源 TLC 双列 Parquet，三项分析为精确摘要、IQR 异常值及区域收入汇总。每个样本重新投影读取数据，不跨请求缓存数据帧；进程已启动，不含 CLI 启动、报表写入、模型推理或网络请求。每条路径先预热，再交错对照五轮。表内为中位数秒，箭头是原筛选 → 新筛选；它不是整机冷启动或 Agent 对话耗时。

| 行数 | CPU 原→新 | 原生 GPU 原→新 | CPU 读取＋GPU 原→新 |
| ---: | ---: | ---: | ---: |
| 20,000 | 0.00549 → 0.00457* | 0.01099 → 0.01105* | 0.01123 → 0.01111* |
| 100,000 | 0.00951 → 0.00950* | 0.01509 → 0.01477* | 0.01528 → 0.01590* |
| 1,000,000 | 0.04049 → 0.04054* | 0.03973 → 0.03885* | 0.03269 → 0.03281* |
| 5,000,000 | 0.18518 → 0.17731 | 0.08508 → 0.08256 | 0.08448 → 0.08204 |
| 20,000,000 | 0.67175 → 0.63062 | 0.20521 → 0.19792 | 0.24505 → 0.24067 |
| 50,000,000 | 1.65559 → 1.58290 | 0.41686 → 0.40640 | 0.54843 → 0.53246 |
| 113,500,327 | 3.77994 → 3.59474 | 0.85982 → 0.82598 | 1.19229 → 1.16488 |

`*` 小规模、短任务的差异不作稳定加速结论。10 万行及以下，最终候选与旧路径执行相同的完整筛选，仍出现测量差异，说明运行环境及噪声不可忽视；百万行三路的样本区间也有重叠。亿级本轮中位数比值为 CPU **1.052×**、原生 GPU **1.041×**、混合 **1.024×**。这些仅是同轮完整三项工作流的原/新比，不代表所有数据集。

单独拆解亿级异常值操作（已驻留的单列，复用精确四分位数，但完整计时掩码、计数、容差和示例提取）：0.30018 → 0.26890 秒，**1.116×**。此列有 10,639,260 个异常值，只需展示前三个；减少全量输出中间帧的收益不会等比例传递给读盘和其他算子。首轮试验发现 CUDA include 路径未设置，频数算法回退；纠正试验环境后重新测量，本文单步骤记录取纠正后的版本，不混用回退结果。

## 验证与回退

全部对照均核对分析结果一致、源文件身份未变。GB10 上 82 项指定测试通过，覆盖 CPU/GPU 示例顺序、重复索引、缺失掩码、末尾稀疏异常、统计复用、混合路由和队列；不等同于全仓库或未知数据全覆盖。Windows 本地也通过新增的七项 CPU 测试，GPU 测试显式跳过；本地缺少 pyarrow 的校准测试由 GB10 完成。

回退开关：`GPU_ANALYSIS_BOUNDED_OUTLIER_EXAMPLES=0`。校准指纹已升版并包含该开关，防止用旧算法的耗时冒充当前路径的训练结果；旧冷/热 profile 会失效，需重新实测，未校准时使用既有保守路由。没有实现在线泛化训练，也没有据这组数据声明硬件极限。

候选代码及实测在本地核心工作区与 GB10 隔离目录，未覆盖 GB10 正式部署，未提交或推送 GitHub。对照工具：[`outlier_examples_probe.py`](../benchmark/outlier_examples_probe.py)，用 `--workflow` 测完整工作流，`--cpu` 测 CPU，`--load-backend cpu_gpu` 测混合路径；默认测独立异常值操作。
