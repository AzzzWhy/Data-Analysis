# GB10 复测与真实上亿行数据实验（2026-09-28）

本轮没有推送 GitHub、替换正式部署、停止模型或降低内存保护阈值。继续使用 GB10、cuDF 25.10.00、pandas 2.3.3，模型服务保持运行。前一轮手动回收了一次可回收文件缓存，本轮未重复回收，缓存会随读取自然增长。

## 已有数据复测

单次 region/revenue 分组求和，包含进程启动、投影读取和计算，不含模型推理。每引擎两次，报告中位墙钟时间。

| 行数 | CPU（pandas） | GPU（cuDF） | CPU/GPU 耗时比 |
|---|---:|---:|---:|
| 2 万，合成小样本 | 0.213 秒 | 1.443 秒 | 0.15 倍，即 CPU 更快 |
| 500 万，原有文件 | 1.556 秒 | 1.662 秒 | 0.94 倍，即 CPU 略快 |
| 2000 万，原有文件 | 6.359 秒 | 2.556 秒 | 2.49 倍 |

与之前的 2000 万行 CPU 6.200 秒、GPU 2.498 秒、2.48 倍基本接近。不能声称回收缓存普遍加快计算。

同样三项查询：revenue 摘要、revenue 异常检测前三个示例、region/revenue 分组求和前三组。每模式两次、交错执行，中位墙钟时间。

| 案例 | 每项独立进程 | 热工作进程（仍读取三次） | 批量（加载一次） |
|---|---:|---:|---:|
| 2 万行，CPU | 0.677 秒 | 0.00763 秒 | 0.00461 秒 |
| 500 万行，GPU | 5.240 秒 | 0.953 秒 | 0.254 秒 |
| 2000 万行，GPU | 7.996 秒 | 3.348 秒 | 1.248 秒 |

2000 万行批量从之前“内存保护拒绝”变为成功。同一 GPU 的独立进程/批量耗时比为 6.41 倍，不是 GPU 相对 CPU 的倍率。500 万行同口径为 20.59 倍，批量耗时与之前的 0.243 秒接近。

本轮工作进程首启另计 0.888 秒，不包含在热态表格中。上述模式结果容差 1e-9 内一致，输入身份未变、结束时会话及热数据帧均为零。没有逐次清空系统页缓存；两次重复只属于工程验证，不是严格冷缓存或性能上限评测。

## 公开数据来源与准备

来源：[纽约市 TLC 官方行程记录](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page)。2017 年黄色出租车全部十二个月，Parquet 元数据核验合计 **113,500,327 行**，原始文件合计 **1,594,686,176 字节（1.485 GiB）**，不是随机生成、复制扩增或抽样数据。

下载与处理脚本：`benchmark/public_tlc_dataset.py`。逐月验证长度、行数，记录来源 URL 和 SHA-256。保留原件，使用分批读取生成两列全量分析视图，不过滤任何行：

- `region` 为 `PULocationID` 的别名：上车出租车区域 ID，不是区域名称。
- `revenue` 为 `total_amount` 的别名：乘客支付总额，不是司机净收入或利润。
- 公共数据由提供方上报，TLC 不保证准确性或完整性；异常值不直接等于欺诈。

本机全量视图 295,481,918 字节，全部 113,500,327 行保留；SHA-256 为 `7c0c6386caac43263748e0bf5655fd0e1968aeadd042dc464a9392c26479752f`。原件与来源清单位于工作区的 `tlc-public-2017`，不入库。

GB10 DNS 不稳定，备用下载仅对官方数据域名使用当前核验的公共 IPv4，URL 与 TLS 主机名校验保持原样，不修改系统 DNS 配置。IP 是瞬时下载条件，不应作为永久配置。

## 上亿行基准

实验脚本 `benchmark/public_data_benchmark.py` 对完全相同的两列 Parquet、三项查询测试 CPU/GPU 各三种执行方式，强制验证引擎、全量行数与结果一致性。先通过 2 万行独立预检，再执行正式全量实验。十二次正式测量均扫描全部 113,500,327 行，摘要、异常计数和示例、分组前三组的输出在容差 1e-9 内一致。

| 三项全量分析的执行方式 | CPU（pandas） | GPU（cuDF） | CPU/GPU 耗时比 |
|---|---:|---:|---:|
| 每项独立进程 | 6.838 秒 | 7.140 秒 | 0.96 倍，CPU 略快 |
| 常驻工作进程，仍读三次 | 6.093 秒 | 2.881 秒 | 2.11 倍 |
| 批量执行，读取一次 | 4.008 秒 | 1.528 秒 | 2.62 倍 |

同一 GPU 的独立进程/批量耗时比 **4.67 倍**；CPU 同样受益于批量执行，不能只优化 GPU 后拿未经优化的 CPU 宣称硬件倍率。首启工作进程另计 0.674 秒，常驻及批量表格不含它；第一次 GPU 单次分析还包括延迟初始化，分项计时保留在原始日志，不能称为全部严格热态。

两次重复按引擎及方式正序、逆序执行，没有重新清空文件缓存，不含 LLM 推理、下载或转换。原始源数据与已有的宽 CSV 不同，列数、格式、可压缩性也不同，因此不能用“1.135 亿行比 2000 万行快”等跨数据集结论证明线性扩展。结果仅代表此全量两列 Parquet 及三项查询。

GB10 用其 PyArrow 版本生成的视图为 301,432,718 字节（SHA-256 `862d59482db4a7d30ed6f3dbadb98bc095b225fbc96fc10976fbf282edbf8cd4`），本机视图为 295,481,918 字节。编码差异不代表行数减少：各自都验证全量行数，正式 CPU/GPU 都读取同一个 GB10 视图。取回 GB10 来源清单后，已核对十二个月原始文件的 SHA-256 与本机全部一致；从本机传入的另一份视图也通过 SHA-256 校验。

一致性结果示例：乘客支付总额均值约 16.3426343，中位数 11.8；IQR 异常计数 10,639,260（9.3738%），只是按规则识别的极端值，不是违规判定。结束时会话、热帧为零，实验输入身份不变。本机执行回归测试十三项再次通过。实验后本地 Qwen 实际推理返回 `OK`，不是仅检查端口；系统可用内存约 67.4 GiB，模型未停止。
